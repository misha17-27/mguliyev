# MGuliyev Studio — сайт

Сайт на PHP без сборки, без зависимостей и без базы данных. Три языка,
панель управления содержимым. Требуется PHP 7.4+, разрабатывается на 8.3.

## Раскладка

```
public/        корень сайта — только это доступно из сети
  index.php, blog/, portfolio/, uslugi/, o-studii/, tseny/, kontakty/
  admin/       панель: только точка входа и оформление
  assets/      css/style.css, js/app.js
  images/      brand/ home/ demo/ works/ groups/ uploads/
  .htaccess robots.txt sitemap.xml send.php

app/           шаблоны, данные и код панели — вне корня сайта
  bootstrap.php  подключается первой строкой каждой страницы
  i18n.php       языки, словарь, склонение числительных
  content.php    данные страниц и настройки
  store.php      чтение и запись правок из панели
  security.php   адрес посетителя, ключи форм, счётчики попыток
  config.php     адрес сайта, языки, почта для заявок
  partials/      head.php foot.php article.php
  data/          catalog.php works.php articles.php packs.php seo.php settings.php
  lang/          ru.php az.php en.php + az/ en/ — накладки для данных
  admin/         boot.php layout.php sections/

site-data/     правки из панели. В репозиторий не идёт, на сервере — ~/site-data
_source/       исходники снимков клиентских сайтов (127 МБ). На хостинг не идёт.
```

Папка каждой страницы и есть её адрес: `public/portfolio/index.php` → `/portfolio/`.

## Запуск

```bash
php -S localhost:5173 -t public router.php
```

`router.php` нужен обязательно: встроенный сервер PHP не читает `.htaccess`,
а языковой префикс `/az/` и `/en/` снимается именно там. Без него эти адреса
отдадут 404.

## Три слоя данных

Содержимое собирается из трёх слоёв, снизу вверх:

1. `app/data/*.php` — русский оригинал, источник правды в репозитории
2. `app/lang/<язык>/*.php` — переводы, тоже в репозитории
3. `~/site-data/*.json` — правки из панели, вне репозитория и вне выкладки

Третий слой перекрывает первые два. Пока в панели ничего не сохраняли,
файлов в хранилище нет, и сайт работает ровно на файлах репозитория.

Для словаря и заголовков в поиске всё иначе: там сохраняются **только отличия**
от файлов репозитория. Если вернуть строке прежнее значение, запись из
хранилища исчезает. Так правки разработчика в репозитории продолжают
доходить до сайта и после того, как заказчик поработал в панели.

## Панель управления

Адрес — `/admin/`. Код разделов лежит в `app/admin/`, выше корня сайта,
поэтому раздел нельзя открыть в обход проверки входа.

**Первый вход.** Пароля в репозитории нет. Откройте `/admin/` — панель создаст
на сервере файл `~/site-data/setup-code.txt` и попросит код из него. Файл виден
только через cPanel → File Manager или SSH, то есть тому, у кого уже есть доступ
к серверу. Введите код, почту и пароль — учётная запись создана, файл удалён.

**Забыт пароль.** Удалите `~/site-data/auth.json` и откройте `/admin/` заново.
Содержимое сайта при этом не трогается. Восстановления по почте нет намеренно:
оно требует отправки писем и само становится способом зайти.

**Что правится из панели:**

| Раздел | Что именно |
|---|---|
| Контакты и цены | телефон, почта, WhatsApp, соцсети, адрес, цены вне прайса |
| Портфолио | отрасли и проекты: домен, описание на 3 языках, снимок, архив |
| Услуги | названия, заголовки, вступления и списки услуг |
| Пакеты и цены | 4 пакета: сумма, состав, кому подходит, чего нет |
| Блог | текст статей по разделам, на каждом языке отдельно |
| Заголовки для поиска | title и description каждой страницы на 3 языках |
| Строки страниц | весь остальной текст сайта — около 380 строк на язык |
| Изображения | загрузка снимков сайтов и вертикальных роликов |
| Почта | куда приходят заявки, отправка через SMTP, проверочное письмо |
| Безопасность | капча Cloudflare Turnstile, проверка заголовков страниц |

**Что не правится и почему.** Ключи направлений услуг (`/uslugi/veb-sayty/`)
и адреса статей участвуют в адресах страниц, а файлы этих страниц лежат в
репозитории. Переименование из панели оставило бы ссылку в никуда, поэтому
новое направление и новая статья заводятся вместе со своим файлом.

## Почта

Заявки уходят через `app/mailer.php`. Способ выбирается в панели:

- **встроенная `mail()`** — ничего настраивать не нужно, но на виртуальном
  хостинге письмо часто либо не уходит вовсе, либо попадает в спам: оно
  отправляется с адреса сервера и не проходит проверку SPF;
- **SMTP** — через настоящий почтовый ящик на домене. Клиент написан здесь же,
  без composer: протокол для нашей задачи — десяток команд.

В разделе «Почта» есть проверочная отправка. При отказе показывается весь
обмен с сервером — видно, на каком шаге встало. Пароль из записи вырезан.

Если письмо не ушло, заявка не пропадает: поля кладутся в
`~/site-data/leads/`, причина — в журнал ошибок сервера.

## Капча

Cloudflare Turnstile, ключи задаются в панели, раздел «Безопасность».
Нет ключей — нет капчи, и всё работает как прежде.

Виджет ставится неявной отрисовкой: в разметке только
`<div class="cf-turnstile">`, своего скрипта не нужно. Поэтому
`script-src` остаётся без `'unsafe-inline'`. `api.js` на страницах сайта
подключает `app.js`, когда до формы остаётся меньше 800px или в неё зашли
с клавиатуры, — не в шапке каждой страницы.

**Политика безопасности страниц правится в `public/.htaccess`, а не в PHP.**
Заголовок из PHP до браузера не доезжает: его перебивает `Header always set`.
Значение продублировано константой `CSP_POLICY` в `app/security.php` —
они обязаны совпадать дословно, и раздел «Безопасность» это проверяет.

**Если капча заперла вход в панель** — удалите на сервере
`~/site-data/security.json`. Она выключится, остальное не изменится.

## Пометки «уточнить»

В текстах сайта стоят видимые пометки `[УТОЧНИТЬ: …]` там, где данных у нас
пока нет: адрес офиса, цена продления, ссылки на соцсети. Это сделано нарочно —
лучше честная пометка, чем выдуманный адрес или цена.

Пометку собирает код из описания поля в `app/data/settings.php`, а не руки.
Заполнили поле в панели — пометка исчезла сама, вёрстку править не нужно.
Список незаполненного виден на первом экране панели.

## Хостинг

Основной домен в cPanel жёстко привязан к `public_html`, и сменить ему
document root из панели нельзя. Поэтому раскладка на сервере такая:

```
~/public_html/   корень сайта          (из public/)
~/app/           шаблоны и данные      (из app/)
~/site-data/     правки из панели      (создаётся, не копируется)
```

Выкладка — cPanel → Git Version Control → Deploy HEAD Commit, по `.cpanel.yml`.
Команды только копируют и ничего не удаляют, поэтому файл, удалённый из
репозитория, в `public_html` останется. После крупной перестройки папку
лучше очистить вручную и развернуть заново.

`~/site-data/` деплой не трогает — иначе правки заказчика пропадали бы при
каждой выкладке. `_source/` на сервер не идёт: это рабочие материалы.

в `public/images/uploads/`. После того как снимок добавлен или заменён,
запустите `php tools/make-images.php`: он делает рядом WebP-копии
(-480, -800, -1200), и сетка берёт их через `srcset`. Без копий страница
просто отдаёт JPEG.

## Языки

Русский — основной, живёт в корне без префикса. Азербайджанский и английский —
на `/az/` и `/en/`. Префикс снимается на уровне сервера (`public/.htaccess`,
локально — `router.php`) и приходит в PHP переменной окружения `SITE_LANG`.

Нет перевода — отдаётся русский оригинал. Не пустота и не ключ: значит,
переводы можно добавлять по одному, и сайт ни в какой момент не ломается.

Склонение после числа живёт в словаре: формы хранятся через вертикальную
черту (`проект|проекта|проектов`), правило выбора — в `plural()`. У трёх
языков оно разное, а в азербайджанском слово после числительного не меняется
вовсе, поэтому держать формы в шаблоне было нельзя.

Статьи блога пока существуют только по-русски. Списки на `/az/` и `/en/`
показывают их как есть, а `hreflang` у самих статей объявляет только `ru`:
заявлять поисковику переводы, которых нет, — прямая ошибка.
